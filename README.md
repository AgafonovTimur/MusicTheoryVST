# Music Theory VST

VST3-версия трёх приложений в одном окне: квинтовый круг, тренажёр нот, тренажёр слуха.
Windows, VST3.

Окно плагина — встроенный в Windows браузер (WebView2), внутри которого открыты те же
самые файлы, что работают в обычном браузере. Файлы приложений вшиты в плагин, интернет
и папки на диске не нужны.

## Сборка через GitHub

1. Создать репозиторий и залить туда содержимое этой папки (файлы `CMakeLists.txt`,
   `README.md`, папки `Source`, `Resources`, `.github` — важно, чтобы `.github` попала,
   без неё сборка не запустится).
2. Вкладка **Actions** → сборка запустится сама после первой заливки. Если нет —
   выбрать слева **Build VST3 (Windows)** и нажать **Run workflow**.
3. Через 10–20 минут (первый раз дольше — качается JUCE) внизу страницы сборки появится
   архив **MusicTheoryVST-VST3-Windows**.

## Установка

Из архива распаковать папку `Music Theory VST.vst3` в:

```
C:\Program Files\Common Files\VST3\
```

В DAW пересканировать плагины. Плагин ставится как инструмент (не как эффект).

Требуется среда выполнения WebView2. На Windows 11 она встроена, на Windows 10 пришла
обновлением ещё в 2022 году, так что почти наверняка уже стоит. Если окно плагина
осталось чёрным — поставить «Microsoft Edge WebView2 Runtime» с сайта Microsoft.

## Что изменилось по сравнению с браузерной версией

**Убрано.** Кнопки «Подключить MIDI» и списки выбора MIDI-входа и MIDI-выхода во всех
трёх приложениях и на всех вкладках. В плагине выбирать нечего: вход и выход — это сама
DAW, подключение происходит автоматически при открытии окна.

**MIDI.** Всё, что играют приложения, уходит в DAW сразу, без LoopMIDI. В квинтовом круге
отправка нот включена с первого запуска (режим «Сыграть в DAW (за раз)»), настройки
velocity, интервала, формата и «Разделить сигнал на каналы» остались на месте и работают
как раньше. Ноты, приходящие в плагин из DAW, попадают в приложения так же, как раньше
приходили с MIDI-клавиатуры.

Ноты, пришедшие из DAW, дальше по цепочке не передаются — инструмент за плагином услышит
только то, что отправили сами приложения. Так же было и в браузере.

**Настройки.** Сохраняются внутри проекта DAW: у каждого проекта свои. Новый проект
открывается с настройками по умолчанию.

**Размер окна.** Окно тянется за правый нижний угол, от 640×400 до 4000×3000, любой
формы — приложение всегда занимает его целиком, полей по краям нет. Пока окно не меньше
1280×800, приложения получают его настоящий размер и ведут себя ровно как в браузере
такого же размера. Если окно меньше, картинка уменьшается целиком, чтобы всё оставалось
на виду. Размер запоминается вместе с проектом.

**Клавиатура.** Плагин забирает фокус клавиатуры, поэтому работают все буквы, цифры,
пробел, `+`/`-`, Y/Н, Z, Q/Й. Пока фокус в окне плагина, пробел не запускает транспорт
DAW — чтобы вернуть управление, кликнуть мимо окна плагина.

**Звук.** В тренажёре слуха вывод стоит на DAW: звучит инструмент на треке, через микшер.
Метроном и звуки в разделе «Ритм» тренажёра нот генерирует браузер, они идут на системный
звуковой выход Windows мимо DAW.

## Как обновить приложения

Заменить файл в папке `Resources` (имена менять нельзя — они прописаны в коде) и запустить
сборку заново. Сами файлы приложений не правились ни на строку: всё, что нужно плагину,
делает `Resources/plugin-bridge.js` — он подменяет хранилище настроек и Web MIDI и прячет
блоки выбора портов. Поэтому обновлённую браузерную версию можно просто класть поверх.

## Состав

```
CMakeLists.txt                     сборка
.github/workflows/build.yml        сборка на GitHub
Resources/index.html               оболочка: три приложения и масштабирование окна
Resources/circle_of_fifths.html    приложения — как есть, без правок
Resources/note-trainer.html
Resources/ear-trainer.html
Resources/plugin-bridge.js         связь приложений с плагином
Source/PluginProcessor.*           MIDI в обе стороны, настройки в проекте
Source/PluginEditor.*              окно-браузер, выдача вшитых файлов
```
